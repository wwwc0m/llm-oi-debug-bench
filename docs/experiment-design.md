# 实验设计：黑盒反馈下 LLM 的算法代码调试能力

## 1. 研究假设

- H1（头版）：TLE 类（算法复杂度不足）修复率显著低于 WA 类（实现错误）——
  TLE 需要算法级重构，黑盒反馈无法提供热点定位信息。
- H2：伪修复（过可见样例、挂隐藏测试）真实存在，且在需要特判的边界类题目上更高。
- H3：黑盒反馈相对白盒反馈（提供失败样例输入输出）造成显著性能损失。
- H4：自我修复（阶段 A）与受控注错（阶段 B）中，模型表现模式一致（补丁倾向 vs 重写倾向）。

## 2. 题库设计（problems/）

每题一个 JSON，字段：

```json
{
  "id": "reskin-min-fee-path",
  "category": "classic | reskin | novel",
  "statement": "……（含示例输入/输出，即选手可见样例）",
  "time_limit_ms": 1000,
  "memory_limit_mb": 256,
  "samples": [{"input": "...", "output": "..."}],
  "hidden_tests": [{"input": "...", "output": "..."}],
  "reference_solution": "problems/solutions/reskin-min-fee-path.cpp"
}
```

- 三类题各 ~8 道（classic / reskin / novel，同前版设计：防训练数据污染）；
- 每题：可见样例 2~3 组 + **隐藏测试 15~25 组**（含边界、极端规模、对抗数据）；
- 隐藏测试由参考解生成输出，人工抽检；
- 时限按参考解实测耗时 × 3~5 倍设置，保证"参考解稳过、O(n²) 解稳 TLE"。

## 3. 交互协议（真实 OJ 平台判题，洛谷为主）

模型每轮可调用的工具（function calling）：

| 工具 | 实现 | 反馈 |
|------|------|------|
| `compile(code)` | 本地 g++ | 编译结果（报错全文） |
| `run_sample(code)` | 本地跑题面样例 | 输入/实际输出/期望输出/退出码 |
| `submit(code)` | **提交真实 OJ（洛谷主力 / CF 备选）** | 每个测试点 通过/未通过；未通过标注 WA/TLE/MLE；内容不可见 |

- 最多 K=10 轮提交；编译失败不计轮；
- 每题每模型重复 3 次（固定 temperature 0.7），报告均值±标准差；
- 全程记录每轮代码、工具调用序列、反馈，供后续策略分析。

### 平台选择与依据

| 平台 | 提交 | 结果读取 | 自编题托管 | 定位 |
|------|------|----------|-----------|------|
| 洛谷 | 非官方接口（Cookie） | 逐测试点状态 | ✓ 个人私有题目 | **主力** |
| Codeforces | onlinejudge 库 | 官方 API | ✗ | 备选 |
| 本地判题器 | 自研 sandbox | 逐测试点 | ✓（tests/） | 兜底/调试 |

**实验节奏约束**：洛谷接口需限速（两次提交强制间隔 ≥60s 保护账号），
单题单模型一轮（≤10 次提交）约 10~15 分钟；全量实验按
题目数 × 模型数 × 3 次重复估算总时长，分批错峰执行。

### 本地判题器实现要点（兜底路径）

- TLE：subprocess 超时（timeout = time_limit）；
- MLE：psutil 轮询峰值内存（近似值，课设可接受）；
- WA：输出比对（忽略行尾空白，与 OI 惯例一致）；
- 沙箱：临时目录运行、超时强杀。

## 4. 阶段设计

### 阶段 A：自我修复
模型仅凭题面写首份代码 → 判题 → 进入调试循环。
（若首份即全过，该题记"首过"，不进循环。）

### 阶段 B：受控注错
对参考解注入四类 bug，各题 × 各类 ≥ 2 个变体：

| bug 类型 | 典型注入 | 预期反馈 |
|----------|----------|----------|
| 边界 | off-by-one、空输入、循环初值 | WA（部分点） |
| 溢出 | int → 需 long long 的规模 | WA（大数点） |
| 复杂度 | 参考解降级为 O(n²) | TLE（大点） |
| 算法思想 | 贪心换为错误贪心 | WA（对抗点） |

注入方式：手写变体 + 人工确认（不依赖自动变异工具，保证 bug 真实自然）。

### 阶段 C：白盒对照
`submit` 反馈改为附失败样例的具体输入/期望输出/实际输出（前 3 个失败点）。
同题同模型对比 → 定位信息的价值。

## 6. 时间线（4~5 周）

| 周 | 内容 |
|----|------|
| 1 | 题库 + 参考解 + 隐藏测试生成与验题；注错变体 |
| 2 | 判题器（compile/run_sample/submit 三工具 + 判 WA/TLE/MLE） |
| 3 | API function-calling 封装；2 题小规模试跑调通闭环 |
| 4 | 全量实验（A→B→C）；统计出图 |
| 5 | 论文撰写（文献综述已有底稿，重点接"验证鸿沟"叙事） |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 模型不擅长 function calling 时协议执行不稳 | 降级方案：文本协议（输出 JSON 指令），runner 解析执行 |
| MLE 在 Windows 上测量不准 | 以 TLE/WA 为主分析；MLE 仅作辅助指标 |
| AI 本地执行代码的安全 | 临时目录 + 超时强杀 + 不出网；题目自编无外部依赖 |
| 模型直接"记住"经典题（首过率虚高） | 三类题对照，重点看 reskin/novel；首过率本身也是分类指标 |
| API 费用/轮次过多 | 每轮截断历史（保留最近 4 轮 + 首轮）；先试跑再全量 |
